# Guided learning: skills, proficiency, MCQ, new topics, and symbol reading

## Context

Mathlificient v1.0.0 ships 33 practice generators and a 185-formula sheet, but it has no idea what a student knows. Questions are picked at random, the quiz's "Got it / Missed it" is **thrown away** when the quiz ends, and there's nothing telling a student what to work on next. Separately, a large slice of the formula sheet has no practice at all — 5 of 15 groups have **zero** generators (Geometry & functions 17 formulas, Differential equations 16, Mensuration 7, Engineering extras 6, Numerical methods 6), and Trig/Differentiation/Integration sit at roughly 1 generator per 8 formulas.

This adds: many more topics, an offline system that assesses what to focus on, proficiency bars, multiple-choice practice, and a symbol/notation section that teaches students to *read* maths aloud with pictures explaining the concepts.

**Confirmed with the user:** both platforms via the shared engine; all four topic areas (coordinate geometry & functions, calculus depth, trigonometry depth, differential equations); symbol coverage through engineering notation.

**This is genuinely large — eight phases.** It is sequenced so each phase ships and is verifiable on-device by itself. Phase 1 alone delivers the proficiency bars and gives Android its first quiz mode. A cut list is at the end.

## Four decisions that shape everything

**1. Proficiency keys off a new `skill` layer (~45), not `topic` (17) or `template.id` (33).**
"Trigonometry 62%" averages cosine-rule arithmetic with compound-angle identities — a student can't act on it. Template ids are the opposite problem: implementation detail, unstable under refactoring, and 66 bars is unreadable. A skill is what a student actually says ("I'm bad at the chain rule"), it's the granularity prerequisites are expressed at, and one skill spanning several templates is a feature — the recommender rotates templates so you can't memorise one shape. Display is **9 area bars → tap → skill bars**.

Templates gain `skill:` (falling back to `'topic:'+slug(topic)` if absent, so nothing breaks) and an optional `alsoPractises:[]` credited at 0.3 weight.

**2. Persist an append-only attempt log, never the computed mastery.**
`proficiency.json` holds `{version, attempts:[{t, skill, tmpl, score, mode, ms, miss?}]}`. Mastery is recomputed on read (<5 ms). This means the **Kotlin side implements zero maths** — `Proficiency.kt` is `StudyLog.kt` with a different filename — the PC cross-window race degrades to "one attempt lost" instead of a clobbered record, and `miss` (which wrong option was picked) gives a misconception log for free, powering feedback like *"you keep using b² + 4ac"*.

Update rule, explainable in one sentence — *"a running average weighted to your recent attempts, that fades if you leave it"*:
```js
alpha = max(0.18, 1/(n+1));  p += alpha * weight * (score - p);  n += 1
weight = 1.0 for MCQ, 0.8 for self-mark   // honest about signal quality
halfLifeDays = 2 * 2^min(streak,5);  recall = 0.5^(daysSince/halfLifeDays)
```
Prerequisites are **soft ordering, not unlock gating** — a shaky prereq multiplies urgency down to a 15% floor, never hides a topic. Locking screens would be patronising and wrong when a student's class has already moved on.

**Cold start matters:** with an empty log every skill is 0 and "focus next" is arbitrary. A skippable **12-question placement check** (one per gateway skill) is part of Phase 1, not optional.

**3. MCQ distractors are declared per template, not generated by string mutation.**
Answers come in four structurally different shapes — bare scalars, labelled (`x = -3`), multi-value (`x = 30°, 150°`), and expressions carrying furniture (`+ C`, `\quad x \ne 3`). Mutating those strings produces obviously-wrong options. Instead:

```js
generate() { …; return { question, steps, answer, viz, w: {a,b,c,disc,r1,r2} }; }  // w = workings bag
distractors(q) { const {b,disc,a} = q.w; return [{latex:…, why:'disc-sign'}, …]; }  // optional
```
`w` is safe because every call site spreads the result and reads only known keys. Distractors are **misconceptions**, not random numbers — `b²+4ac`, population-vs-sample SD, forgetting to negate the perpendicular reciprocal. `practice-mcq.js` enforces label consistency (every option carries the same `x =` prefix, or the odd one out gives itself away), falls back to harvesting *other instances' answers* from the same generator, and if still short returns `null` so the question silently uses the existing self-mark path. **All 33 existing templates keep working from day one.**

**4. Symbol pictures reuse `practice-viz.js`, not a new renderer.**
It already gives HiDPI, theme-awareness, and primitives (`makePlot`, `drawArrow`, `curve`, `dashedV/H`, `label`). Add 8 spec types: `numberline` (`< ≤ |x| ∈ [a,b)`), `setdiagram` (`∪ ∩ ⊂`, `P(A∩B)`), `riemann` (`Σ → ∫`), `tree` (`P(A|B)`), `stack` (`Σ Π`), `contourpath` (`∮`), plus `vectorfield` (`∇`) and `surfaceslice` (`∂`) which are the only genuinely new drawing code (~100 lines combined). Symbol entries carry `confusableWith`, which drives **both** the "commonly confused with" teaching card and the quiz distractors from one field.

## Phase 2 — implementation

### Context

Phase 1 shipped the bars, but **every grade is self-marked** — the student decides whether they got it right, and the model discounts that to 0.8 because it's a noisy signal. Multiple choice is what turns the bars from "roughly where you think you are" into something measured.

It also closes a loop Phase 1 deliberately left open: `topMiss()` in `practice-prof.js:225` already reads a global `MISCONCEPTIONS` that **does not exist yet**, and `attemptFrom()` already accepts a `miss` argument nothing passes. Recording *which* wrong answer was picked is what powers feedback like *"you keep using b² + 4ac"* — on the question itself and on the progress screen.

**Decided with the user:** default mode stays **Work it out** (paper-first; MCQ is opt-in and remembered); distractors on **all ~30 templates that can support them**; a wrong pick **locks and explains** — one pick, one score.

### Four corrections to the original sketch

The original Phase 2 note said "`distractors(q)` reads `q.w`". Reviewing against the real code found four problems that would have shipped broken.

**A. Options are built once in `buildQuestion()`, not at display time.**
`buildQuestion()` (`tools/practice.js:100`) spreads `...template.generate()` and **discards the template** — so a `distractors(q)` called later has nothing to call it on. `practice-quiz.js:31` is worse: it pre-generates the entire queue before the first question is shown. Building the options at question-construction time fixes this and four other things at once:

```js
function buildQuestion(template) {
  let q = null;
  for (let tries = 0; tries < 5; tries++) {
    const { w, ...gen } = template.generate();   // w stays a local, never stored
    q = gen;
    const choices = buildChoices(gen.answer, template.distractors, w);
    if (choices) return { ...gen, choices, formulas, templateId, topic, skill };
    if (!template.distractors) break;            // no MCQ for this template at all
  }
  return { ...q, choices: null, /* … */ };       // self-mark, this instance only
}
```

- `w` never becomes a stored key, so it can't ride the `worksheet:open` IPC payload (`practice-quiz.js:169` → `main.js`) or make the question record's shape template-dependent.
- Options are **frozen with the question** — stable across re-render, mode toggle and quiz review. Derived at display time they would reshuffle under the student.
- No `PRACTICE_BY_ID` lookup is needed (it doesn't exist), and the quiz queue needs no special case.
- `showTutorQuestion()` naturally produces no `choices` → falls back to self-mark with zero extra code.
- Regeneration-on-collision becomes possible, because we're still upstream of `show()`.

**B. Split "how it was graded" from "which flow it happened in".**
`gradeMode` currently means the *flow* (`self` / `placement`), but `WEIGHT` in `practice-prof.js:24` reads it as the *grading method*. MCQ breaks the conflation in both directions: an MCQ answered inside a quiz would log `mode:'self'` and silently get weight 0.8, and an MCQ during placement would lose the `placement` tag that the log comment exists to preserve.

- `mode` ∈ `mcq` | `self` — derived at record time from **how the answer actually arrived**. Drives `WEIGHT`.
- `flow` ∈ `practice` | `quiz` | `placement` — new optional field on the attempt. Drives nothing today; keeps the log legible and lets a later phase segment by it.
- **Placement is always self-mark.** Not all 12 gateway skills have distractors, and seeding every bar on a fresh install from two different weightings *and* two different chance floors is worse than a uniform seed.

**C. Correct for guessing, and record the option count.**
A 4-option question has a 25% floor. `p` converges to the mean score, so a student who genuinely knows half converges to `0.5 + 0.5×0.25 = 0.625` — **above `SOLID` (0.60)** — where self-marking puts the same student at 0.5. Switching a skill to MCQ would flip its bar amber→green with no change in ability, and `recommend()`/`dueForReview()` would follow.

Fix in `computeProficiency`, for attempts carrying `k` only:
```js
const s = a.k ? clamp((a.score - 1 / a.k) / (1 - 1 / a.k), 0, 1) : a.score;
```
A pure guesser now converges to 0; knows-half converges to 0.5. Everything Phase 1 wrote, and every self-mark, has no `k` and is untouched. **This is safe precisely because the log is append-only and mastery is recomputed on read** — changing the formula needs no migration, which was the whole point of that decision.

**D. Nothing may be revealed before the pick.**
`#nextStep` and `#showAnswer` stay live regardless of mode, and the last step of nearly every template *is* the answer (`quad-factorise` step 4 is literally `x = 3, x = -5`). Banking a 1.0 objectively-graded score after reading the answer is worse than the self-mark honesty system it replaces. Also, `practice.js:212` reveals Got it / Missed it whenever `!graded && current.skill`, so pressing "Show answer" in MCQ mode would put **both grading paths on screen live at once**.

- In MCQ mode, `#nextStep` / `#showAnswer` are `disabled` until a pick lands; after the pick they become the "explain it" affordance.
- `#grading` is hidden **unconditionally** in MCQ mode, not via the `graded` flag.
- Belt and braces: if `revealed > 0` when a pick lands, record `mode:'self'`, `score: 0.5` (the value `attemptFrom`'s docstring already reserves for "right after a hint") instead of `mcq` 1.0.

### Correctness contract for distractors

String inequality against the answer is not enough — three ways a "wrong" option is actually right:

1. **Same formatter, always.** A distractor is authored with the *same template literal* as the answer, using the same `PR.lead` / `PR.xt` / `PR.ct` helpers. Otherwise `x^{3}` vs `x^3` render identically but pass string dedupe.
2. **Compare on a normalised form** — strip whitespace, `\left`/`\right`, braces around single tokens, `\tfrac`↔`\frac`. Compare normalised; display the original.
3. **Value-equality traps, listed per template.** `indices` answers `x^{a+b-c}` with the exponent spanning **0–12**: when it's 0 the answer is `x^{0}` and a distractor of `1` is also correct. Same for `x^{1}` vs `x`.
4. **Never author a permutation of a multi-value answer.** `x = 3, \ x = -5` and `x = -5, \ x = 3` are the same answer. The harness catches these by comparing sorted number-multisets alongside the shape signature.
5. **Templates return 4–6 candidates, best first**, so dedupe has slack. Required for the small answer spaces: `log-laws` has only 5 distinct values (integers 2–6), `solve-exp` 2–5 (2–4 when the base is 5), `trig-solve` just 3 fixed option sets.
6. **Fewer than 3 surviving distractors → regenerate** (bounded, 5 tries; `generate()` is pure and microseconds-cheap), then fall back to self-mark **for that instance only**, never disabling the template. Never pad with junk and never ship a 3-option MCQ — that's a 33% guess floor still weighted as if it were 4.

`MISCONCEPTIONS` lives in `practice-data.js` (both `practice.html` and `progress.html` already load it, and it's where the `why` keys are authored, so a distractor and its sentence are added together). Shape:

```js
MISCONCEPTIONS['disc-sign'] = {
  label: 'using b² + 4ac',                                  // plain text, reads after "you keep …"
  hint: 'That is b² + 4ac. The discriminant is b² − 4ac.',   // plain text, shown next to the options
};
```

Both fields are **plain text, never LaTeX** — `label` is spliced into a sentence rendered with `textContent` on the progress screen. `topMiss()` in `practice-prof.js:229` currently does `MISCONCEPTIONS[why] || why`, which would render `[object Object]` against this shape and leaks the raw key on a typo — it must read `.label` and **return null** for an unknown key. Only ever set `miss` on a **wrong** pick: `computeProficiency` counts `a.miss` with no score guard.

**Two template fixes required first:**
- `exact-value` — all three `pairs` sum to 90, so the answer is **always literally `1`** and the `\tfrac{\sqrt{3}}{2}` branch is dead code. MCQ here would teach "always pick 1". Add pairs that don't sum to 90 before giving it distractors.
- `matrix-det-inv` — **excluded from MCQ with a comment saying why**: the question asks for `det A` *and* `A⁻¹`, but the `answer` string carries only the determinant, so an option list of determinants doesn't answer the question asked.

### Two platform traps

**`applyPaper` will stomp the correct/wrong colours.** `practice.js` injects `select,button{color:…!important;background:transparent!important}` and `PracticeSpaceActivity.paintWeb` calls it on every paper change — so in the Studio, the green/right and red/wrong states would be overridden. This already quietly affects `#gotIt`/`#missedIt`. Express option state via `outline`/`box-shadow` (untouched by the injected rules) **and** add explicit `.mcq-option.correct` / `.wrong` rules to the injected stylesheet.

**`.mini` arrives after the scripts run.** `PracticeActivity` injects the class in `onPageFinished`, so any load-time read of `classList.contains('mini')` sees `false`. Decide the mode lazily inside `show()`. The popup only ever displays tutor-pushed questions, which have no template and therefore never have options — so `.mini` is treated as **self-mark only**, otherwise it would show "no options for this one" on every question it will ever display.

### Mode toggle

- Two states, `Work it out` (default) and `Multiple choice`, persisted in `localStorage` under a namespaced key (`mathlificient.answerMode`). `file://` pages share one bucket across `practice.html` / `progress.html` / `formulas.html`, hence the namespace.
- **A mode change takes effect on the next question**, with a one-line note saying so. Switching mid-question is otherwise undefined and every option is bad: after a pick, `graded` is true, so the self-mark row stays suppressed and in a quiz `advance()` never fires — the quiz stalls with no way forward.
- Where the current question has no `choices`, MCQ mode says **"No options for this one — mark yourself"** rather than silently reverting.

### Verification

**`tools/check-practice.js`, ~500 generations per template** — the core defence, since the authoring work is where the bugs will be:
- exactly 4 options; all distinct under the *normalised* comparison; the answer's normal form appears exactly once
- no option is a permutation of the answer (sorted number-multiset check)
- every option shares the answer's shape signature (digits → `#`), reported as a failure per template — this is the label-consistency check, done here rather than at runtime so a legitimately-varied shape is never silently stripped of MCQ
- every `why` key emitted by any `distractors()` exists in `MISCONCEPTIONS`, and every `MISCONCEPTIONS` entry is reachable
- the existing no-`0x`/`1x` artifact scan, extended over distractor strings
- fallback rate per template (how often 5 regenerations still fail) — anything above a few percent means the distractors are too collision-prone

**Model tests** (extend the Phase 1 suite): a pure guesser at 4 options converges below `SHAKY`; a knows-half student converges to ~0.5 not 0.625; an attempt with no `k` is unchanged; MCQ-in-a-quiz records `mode:'mcq'`, `flow:'quiz'`; placement records `mode:'self'`.

**PC, Electron harness**: pick right → green, locked, score 1 at weight 1.0; pick wrong → red + the specific hint + correct answer highlighted + `miss` recorded; reveal steps first then pick → recorded as `self` 0.5, not `mcq` 1.0; mode switch mid-question doesn't stall a quiz; a 5-question MCQ quiz runs to a summary; ink `<details>` collapse→expand preserves strokes and the page fits at min size.

**Android, phone-sized harness** (the Phase 1 bridge stand-in at 360 dp): grid is 2×2 with 44 px targets and no horizontal overflow; `.mini` hides the toggle and grid; `applyPaper('#1C1C1E','#F0F0F0')` leaves correct/wrong distinguishable.

**On-device** (needs the tablet connected — Phase 1 could not do this): answer 10 MCQ questions, force-stop, confirm bars and misconceptions persist; confirm the progress screen's "you keep …" line appears after repeating one slip.

## Gotchas that will bite if missed
